## 説明文

```
飲食店のシフトを組むエージェント「kumu」のデモです。
どう組んでも人が足りない週には、シフトを出さずに「組めません」と返します。

作りはじめたときは「言語モデルにシフトは作れない」と考えていました。
測ったら間違いで、6回のうち2回は制約違反ゼロで組めています。
ただし同じモデル・同じ条件でも、1回目は違反11件、3回目は1件。
守れているかどうかは、出してみるまで分かりません。
希望をどれだけ通せたかは、モデルが42〜53%に対してソルバーが70%でした。

章立て
0:00 希望を出す（1時間刻みのドラッグと予想給与）
0:13 全員のシフト
0:29 組めない週
0:58 確認待ち（希望欄に混ざった指示文）
1:23 自分のシフト
1:31 代われる人を探す

仕組み
割り当てを解くのは OR-Tools の CP-SAT で、言語モデルは自然言語の読み取りだけに使っています。
組めないときは、同時に成り立たない条件を返します。CP-SAT が返す集合は最小ではないので、
110件を12件まで絞っています。
「なぜ自分の希望が通らなかったか」は文章を生成しません。その希望を必ず通す条件で解き直して、
何と入れ替わるかを並べます。
希望欄は本人が自由に書ける場所なので、読み取った結果は候補どまりにして、店長の確認を通します。

リンク
GitHub: https://github.com/muroshima/kumu
記事: （Qiita の URL）

AI HACK 2026 提出作品です。店もスタッフも架空で、実在のデータは使っていません。

使ったもの
OR-Tools CP-SAT / OrcaRouter / Python / Playwright + edge-tts + ffmpeg
（この動画も画面録画ソフトを使わず、スクリプトで生成しています）
```

## サムネイル

`docs/thumbnail.png`（2560×1440 / 0.73MB）を使う。YouTube の上限 2MB 以内。
`docs/thumbnail.jpg` は 1280×720 の軽い版で、記事の先頭画像にも使える。

## 公開設定のメモ

- 「子ども向けではない」を選ぶ
- 章立ては説明文の先頭ブロックに 0:00 から連続で書いてあるので、そのまま章として認識される
- 限定公開にするなら、記事からのリンクは有効なまま残る
